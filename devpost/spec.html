First Defense

One static web page. It doesn't think — it asks a model to examine the pasted message as evidence, never instructions, and forces the answer into a fixed shape with no slot for a verdict.

Also static content: phrases.js (the always-visible scam-phrase list and the fixed "verify with a number you look up yourself" copy — which the model cannot touch). No server, no database, no backend anywhere in the picture.

The result shape — where "never a verdict" is enforced

FieldMeaningCan be a verdict?
askWhat the sender wants you to do, plain language (may be empty)No
tactics[]Named tactic + one plain sentence each (may be empty)No
similarScams[]0–3 real scam patterns in the same languageNo
pushesPhoneNumberA re-checkable hint from the model — not the only gateNo
calm next stepStatic UI copy — always shown, never model output

There is no safe, isScam, confidence, or score field anywhere. additionalProperties:false means even an unknown key is rejected at the provider. A verdict isn't just forbidden by a prompt — there is nowhere to write one.

How the prompt-injection defense actually works

The pasted message is handed over as its own user-role message — never stitched into the system prompt and never dropped inside a delimiter it could close. It is the thing being watched, not an order being received.

LayerWhat it stops
Role separation (system vs user message)"Ignore your rules"—style text is just content to analyze
No verdict field + additionalProperties:falseAn injected verdict has no slot, and unknown keys are rejected
Hard max lengths on every stringDumping a paragraph of instructions into a two-sentence field
Attributed-text framingA hijack saying "wire money" renders as a quote of the message, not the tool speaking
textContent renderingModel text never parsed as HTML or script
Static calm-next-step copyThe one protective line can't be suppressed by the model at all

Where it runs · files · failure modes

Where it runs & how to try it›
  • Modern browser. No Node needed to use it. Dev server for testing: npx serve .
  • Live lookup needs a key: pasted by the visitor (kept in their browser) or a local gitignored env.js
  • No key → it says so, never a fake result.
  • Demo: run locally with a key, paste a real scam text, show the breakdown, then open a "Previous finds" entry
  • Deployment optional. Public URL works only after a visitor adds their own key — deliberate and key-safe

Important failure modes7 ›
  • No key → state 4: explains, offers the key control, no fake result NO_KEY
  • Call fails / times out / CORS blocked → state 5: calm message + verification guidance NETWORK
  • Off-shape response → rejected; at most one retry; then state 5 OFF_SHAPE · bounded at two calls
  • Empty / nonsense input → asks for a message first EMPTY
  • Input too long → asks for a shorter message; nothing oversized is sent
  • localStorage corrupt → history starts empty, app keeps working
  • Instructions aimed at the tool → analyzed as evidence; six defense layers above apply
Open issues & build-step 04 ›
  • Build-step 0, before any UI: make one real browser call to the provider — confirm CORS, current model name, structured-output parameter names. Evidence: a result rendered on the page. A CORS surprise would otherwise invalidate the architecture after the UI is built.
  • Model name, pricing, parameter names — unverified at spec time
  • On-screen copy for the "no ask, no tactic" case — settle during build
  • Concrete fonts and hex values — intent is fixed; build picks values
Caught by the pre-build review & fixed14 ›
  • Default provider changed to Gemini (DeepSeek fallback) — OpenAI doesn't allow direct browser calls, so the original pick would have failed build-step 0
  • Pasted text sent as its own user message — no delimiter to break out of
  • Injection claim made honest and hardened; the guarantee is stated precisely
  • API-key entry UI added — the bring-your-own-key path now exists on screen
  • Five render states enumerated to match the PRD
  • Empty ask / tactics representable, with UI copy
  • Error codes defined and mapped
  • env.js loaded via guarded dynamic import so a missing file doesn't 404 the module graph
  • Phone-number guidance no longer gated only on a model boolean; raw text re-checked
  • Retry reconciled with "one LLM call" — bounded at most one retry
  • Input length cap added
  • Storage shape fixed; UUID ids; label sanitization
  • Sidebar responsive behavior specified (toggle below ~800px)
  • PRD's "nothing else persists" clarified — the key is the one exception

Honest gut check

Sharp

Every PRD behavior has a home, the file tree is real and small, and the injection story is now layered rather than a single claim — the calm next-step line being static copy is the cleanest part of the whole design.

Still soft

The provider choice is genuinely unverified: if neither Gemini nor DeepSeek allows the browser call, you'll add a serverless function. That's exactly why it's build-step 0. It's sized to a small proof of concept otherwise.
