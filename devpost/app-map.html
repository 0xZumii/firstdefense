A one-page guide to the app you built: what the pieces are, how one real action moves through them, and where to start when you want to change something.

What it is, in one breath

Paste a suspicious message. One button. You get four things back: the ask in plain language, the pressure tactic being used, real scam patterns that look like it, and a calm next step. It never says a message is safe or unsafe.

Five small files do all the work. There is no server, no database, and no build step - just a page, four JavaScript modules, and your browser's own storage.

Then app.js renders it: the flat ask, the accent-colored tactic box, the matching scams, and - only if a number is really in the message - the "verify it yourself" line. The calm next-step text and the phrase list come from src/phrases.js, which the model can never touch.

A 3-stop route through the code

Stop 1 - the button and the flow›
  • src/app.js · async function runFind() This single function is the whole journey: check the input, call the model, save the find, render the result. Start any debugging here.
Stop 2 - why injection cannot win›
  • src/api.js · SYSTEM_PROMPT and the contents array The rules live in the system message. The pasted text is a separate user message - evidence to examine, never instructions to follow. That separation is the first line of defense.
  • src/schema.js · validateResult() and FORBIDDEN_KEYS Even if the model were talked into inventing a "verdict" field, this rejects it. The shape has no slot for a verdict, so there is nowhere for one to render.
Stop 3 - where content and history live›
  • src/phrases.js · GENERAL_PHRASES, NEXT_STEP_TEXT All fixed copy. The protective "verify with a number you look up yourself" line lives here precisely because the model must never be able to change it.
  • src/store.js · addFind(), getFinds() Your "Previous finds" panel. Append-only, newest-first, and tolerant of corrupt storage - it returns an empty list rather than crashing.

A practice to reuse

Make the wrong output impossible, not just forbidden. The prompt asks the model never to give a verdict, but the real protection is that the result shape has no verdict field and unknown keys are rejected (src/schema.js). Then it was tested with seven real attacks (injection-test.html).

On your next project, ask two questions early: "What would the wrong output look like?" and "Can I make that impossible rather than ask nicely?" Then attack your own thing before shipping it. That is a habit worth carrying into any project that trusts a model's answer.
