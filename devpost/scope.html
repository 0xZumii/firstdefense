First Defense

Paste a suspicious message. Get the plain-language version of what it's really asking you to do — and the pressure tactic it's using. Never told "safe" or "unsafe."

Renamed from "Pause" — approved

The Unique Kernel

It refuses to give a verdict. Instead of chatbot prose, it returns the same predictable shape every time: the ask restated in flat, plain language, the manipulation tactic named, and a short list of real scams using that same language.

Delete the "never says safe" rule and the fixed output shape, and this is just ChatGPT with a text box. Both are the point.

How it flows

1 · who Mom or grandparent Got a text that feels off. Doesn't know how to prompt an AI.
→
2 · input Paste the message One big box. One button. Pasted text only.
→
3 · engine Translate, don't judge One LLM call, locked to a fixed structure. Ignores instructions hidden in the message.
→
4 · output Flat ask + named tactic The message's power to panic you, spelled out.
→
5 · back Calm next step Slow down. Verify via a number you look up yourself.

The loop: scams keep arriving, so they come back the next time a message feels wrong. No account, no chat, no follow-up prompting — one shot, in the moment, alone.

What comes back — always the same shape

  1. The plain version of the ask What they actually want you to do.
    "They want you to send $400 in gift cards and read them the numbers."
  2. The tactic the message is using The thing making you feel rushed or scared.
    "This message uses urgency and fear to rush you."
  3. A few real scam patterns that look like this one So the pattern sticks for next time.
  4. One calm reminder Don't act under pressure. Verify through a number you look up yourself.
The "oh, that's the thing" moment: the ask appears flattened into boring plain language right next to the named tactic — the message's power to panic you visibly drains out of it. Beat to capture in the 1–3 minute demo video

Who it's for

Now The target user

The learner's mom and grandparents — older, non-technical people who are the prime targets of fake-financial social engineering: fake delivery fees, "your account is locked," tech-support calls, gift-card and romance scams.

Today What they do instead

Take the message at face value, or forward it to a family member and hope someone answers. This tool has to be usable by them, alone, in the moment — not something that needs someone else to explain it.

Now · Later · Cut

In the proof of concept6 items ›
  • One page, one large paste box, one button
  • Pasted text only as input
  • Fixed output structure: flat ask → named tactic(s) → matching scam examples → one calm action reminder
  • Works on a phone-sized screen
  • Never emits a safe/unsafe verdict
  • One LLM call with a guardrail that holds the output shape and resists instructions hidden inside the pasted message
Worth doing, not now6 items ›
  • Link handling — show the URL, flag a suspicious domain (string analysis only)
  • Screenshot / image input (OCR)
  • Transaction and wallet-approval scanning The web3 angle
  • Read-aloud and translation
  • Saved history
  • A "share with my family" option
Explicitly cut4 items ›
  • Any safe/unsafe verdict Deliberate and central: false positives and false negatives would both hurt users and destroy trust.
  • Fetching and rendering arbitrary pasted links A separate attack surface and a build-time sink; not needed to prove the kernel.
  • Accounts, chat history, follow-up prompting The product is one-shot and prompt-free by design.
  • Transaction scanning Web3 scope; interesting later, adds nothing to the core proof.

The rule that gives it a spine

It never says this is safe or this is a scam. False negatives and false positives both exist. A better-informed user is more powerful than one taking things at face value — so the tool translates and educates instead of ruling.

Why this matters

Security is what excites the learner: "i love helping people and the internet is a better place when users are protected." Scams and cybercrime are rising fast because AI lets threat actors vibe-code malware and phishing sites cheaply — while the people being targeted are the ones least equipped to spot it.

A junior in the security field focused on web3 best practices for keeping funds and personal information safe, they want this to be a first layer of defense for people who have nothing else to rely on.

Honest gut check

Sharp

The never-says-safe rule gives the tool a spine and answers the learner's own goal about output security. Fixing the user to mom and grandparents makes the demo land. Cutting link-fetching is correct.

Still soft

The name is a placeholder, look-and-feel is only a mood until the PRD, and the guardrail against a scammer hiding instructions inside the message is stated but unproven. That's the riskiest claim in the plan — the spec needs to take it seriously.

Open risk carried into the PRD & spec

A scam decoder that can be talked out of doing its job by text hidden in the pasted message is worse than no tool at all. How untrusted input is isolated, and how the output is validated, is likely the single most important design decision in the build.
